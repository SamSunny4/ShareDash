Why Traditional Sharing Fails & How ShareDash Solves It

Quick Share, AirDrop, and LocalSend choke when Wi-Fi routers are missing, congested, or restricted. ShareDash bypasses the network stack with physical point-to-point hardware aggregation.

Simultaneous Multipath Aggregation

Why choose between USB or Wi-Fi when you can use both? ShareDash splits multi-gigabyte files into adaptive chunks and streams them concurrently across USB 3.x and 5GHz Wi-Fi without packet collisions.

78.7+ MB/s Combined Real-World Throughput

100% Zero-LAN & Routerless

No home router, no office Wi-Fi, and no cloud relays required. ShareDash works in the middle of a desert, on an airplane, or in high-security air-gapped facilities over direct device-to-device hardware links.

0 ms Cloud Latency & Zero Telemetry

Smart 5GHz Hotspot Orchestration

Windows Internet Connection Sharing (ICS) bottlenecks PC hotspots to ~10 MB/s. ShareDash intelligently commands the Android phone via BLE to switch off client Wi-Fi and host an uncapped 5GHz Direct Group Owner at 48+ MB/s.

4.92× Faster than Windows SoftAP

Zero-Corruption Cryptographic Verification

Every frame is guarded with CRC32 framing. Every chunk is verified against BLAKE3 / SHA-256 hashes, and streams are secured with AES-256-GCM authenticated encryption. Corrupted chunks are re-requested on the fly.

100% Bit-Verified Integrity

Out-of-Order Sparse File Reassembly

High-speed chunks arrive concurrently across channels. The Android Kotlin engine utilizes direct-offset Java NIO FileChannel sparse allocations, writing chunks immediately without intermediate caching.

2MB - 64MB Adaptive Chunk Pipelining

Interactive Wifite-Style ANSI CLI

Engineered for power users. An interactive terminal wizard with hardware inspection, Bluetooth radar scanners, live multi-channel speedometers, and instantaneous transfer telemetry.

Pure Rust Zero Runtime Overhead

1

BLE Discovery & Radar

Phone advertises ShareDash GATT Service UUID. The Windows PC discovers the phone via BLE in under 800ms.

2

Band Freeing & 5GHz AP

Phone automatically disables client Wi-Fi to free the antenna chip, provisions a 5GHz direct group, and sends credentials over BLE.

3

Parallel Multipath Stream

PC binds to USB-C port forward and 5GHz Wi-Fi simultaneously, launching 3 in-flight parallel workers per transport.

Direct-Offset Sparse File Writing (Zero Cache Thrashing)

Traditional transfer tools buffer files in RAM or temporary caches. ShareDash pre-allocates the entire file on disk using sparse allocation, allowing chunks arriving out-of-order over USB and Wi-Fi to be written directly to their absolute byte offsets using FileChannel.write(buffer, offset).

fileChannel.write(chunkBuffer, chunkManifest.byteOffset); // Zero intermediate copies

Everything You Need to Know

Clear answers to questions regarding performance, offline operation, and security.

Absolutely not. ShareDash is 100% routerless and works without internet. It connects directly device-to-device using a USB-C cable and an automatically provisioned 5GHz Wi-Fi Direct mobile hotspot.

Windows Mobile Hotspot uses Internet Connection Sharing (ICS), which performs software-based NAT packet inspection and requires an active internet connection, capping speeds to ~10 MB/s. In contrast, Android's Wi-Fi Direct Group Owner operates directly in hardware with zero NAT filtering, reaching unthrottled line speeds of 48+ MB/s.

ShareDash assigns each chunk an index, byte offset, and individual cryptographic hash. The receiver uses Java NIO FileChannel to write chunks directly into their exact byte positions on disk regardless of arrival order. Once all chunks arrive, the master SHA-256 hash is computed and verified before marking the file complete.

ShareDash's dynamic work-stealing scheduler immediately detects socket termination on the USB pipeline. In-flight chunks that were lost are automatically re-queued and dispatched over the active 5GHz Wi-Fi channel with zero interruption to the user.

Yes. All communication is protected with authenticated AES-256-GCM encryption using an ephemeral session key derived during the 3-way pairing handshake. No telemetry, account registrations, or third-party servers exist.
