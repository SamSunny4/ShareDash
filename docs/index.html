Overview

Why traditional sharing fails

Quick Share, AirDrop, and LocalSend rely on routers, congested networks, or cloud relays. ShareDash bypasses the network stack entirely with physical point-to-point hardware aggregation.

Simultaneous Multipath Aggregation

Splits multi-gigabyte files into adaptive chunks and streams them concurrently across USB and 5GHz Wi-Fi without packet collisions.

100+ MB/s Peak real-world speed

100% Zero-LAN & Routerless

No router, no office Wi-Fi, no cloud relays. Works in the middle of a desert, on an airplane, or in air-gapped facilities.

0 ms Cloud latency & zero telemetry

Smart 5GHz Hotspot Orchestration

Windows ICS bottlenecks PC hotspots to ~10 MB/s. ShareDash coordinates with Android to host an uncapped 5GHz Direct Group Owner at 48+ MB/s.

4.92× Faster than Windows SoftAP

Cryptographic Verification

Every frame guarded with CRC32, every chunk verified against SHA-256 hashes, streams secured with AES-256-GCM authenticated encryption.

100% Bit-verified integrity

Sparse File Reassembly

Chunks arrive out-of-order across channels. Android writes directly to absolute byte offsets via NIO FileChannel — zero intermediate caching.

2–64 MB Adaptive chunk pipelining

Interactive ANSI CLI

Terminal wizard with hardware inspection, Wi-Fi Direct & UDP radar scanners, live multi-channel speedometers, and transfer telemetry.

Zero-LAN Discovery & Radar

Band Freeing & 5GHz Direct AP

Parallel Multipath Stream

PC binds to USB port forward and 5GHz Wi-Fi simultaneously, launching 3 in-flight parallel workers per transport.

Direct-Offset Sparse File Writing

Traditional transfer tools buffer files in RAM or temporary caches. ShareDash pre-allocates the entire file on disk using sparse allocation, allowing chunks arriving out-of-order over USB and Wi-Fi to be written directly to their absolute byte offsets using FileChannel.write(buffer, offset).

fileChannel.write(chunkBuffer, chunkManifest.byteOffset); // Zero intermediate copies

Frequently asked questions

Windows Mobile Hotspot uses Internet Connection Sharing (ICS), which performs software-based NAT packet inspection and requires an active internet connection, capping speeds to ~10 MB/s. Android's Wi-Fi Direct Group Owner operates directly in hardware with zero NAT filtering, reaching unthrottled line speeds of 48+ MB/s.

ShareDash assigns each chunk an index, byte offset, and individual cryptographic hash. The receiver uses Java NIO FileChannel to write chunks directly into their exact byte positions on disk regardless of arrival order. Once all chunks arrive, the master SHA-256 hash is computed and verified.

ShareDash's dynamic work-stealing scheduler immediately detects socket termination on the USB pipeline. In-flight chunks that were lost are automatically re-queued and dispatched over the active 5GHz Wi-Fi channel with zero interruption.
